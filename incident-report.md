\# Windows SOC Investigation Lab\## Case Overview\*\*Case Type:\*\* Authentication and Endpoint Activity Investigation\*\*Environment:\*\* Windows 11\*\*Host:\*\* GREGPC\*\*Test Account:\*\* SOC\_Test\*\*Investigator:\*\* Greg Berard\## ObjectiveInvestigate simulated authentication failures and endpoint process activity using native Windows security logging and Event Viewer.\## Investigation SummaryA controlled security monitoring exercise was performed against a dedicated local test account. Multiple failed authentication attempts were generated to simulate a potential brute-force or unauthorized access scenario.The resulting Windows Security events were analyzed to determine:\- Account targeted\- Authentication type\- Source of authentication attempts\- Authentication failure reason\- Process execution associated with the test account\- Parent/child process relationships\- Whether observed activity represented malicious behavior or expected testing activity\## Findings\### Authentication ActivityWindows Event ID 4625 recorded multiple failed authentication attempts against the `SOC\\\\\\\\\\\\\\\_Test` account.Observed evidence:\- Target account: `SOC\\\\\\\\\\\\\\\_Test`\- Logon Type: `2`\- Workstation: `GREGPC`\- Source IP: `127.0.0.1`\- Status: `0xc000006d`\- SubStatus: `0xc000006a`\- Authentication Package: `Negotiate`The source address of `127.0.0.1` indicated that the authentication attempts originated from the local system.The substatus code `0xc000006a` indicated an incorrect password.\### Process ActivityWindows Event ID 4688 was used to investigate process creation.Observed process activity included:\- `cmd.exe` → `whoami.exe`\- `cmd.exe` → `HOSTNAME.EXE`\- `cmd.exe` → `ipconfig.exe`\- `runas.exe` → `powershell.exe`\- `powershell.exe` → `conhost.exe`The `whoami`, `hostname`, and `ipconfig` commands represent common system and network discovery activity.\### Initial AssessmentThe observed discovery commands could be associated with legitimate administration or attacker reconnaissance. Because the commands alone do not establish malicious intent, the activity should be classified as suspicious and investigated further rather than immediately classified as malicious.The authentication failures were ultimately determined to be expected laboratory activity because the events originated locally and were intentionally generated using the `SOC\\\\\\\\\\\\\\\_Test` account.\## Analyst ConclusionThe investigation demonstrated the ability to:1\. Identify authentication failures.2\. Extract relevant security event fields.3\. Correlate authentication activity with endpoint process activity.4\. Analyze parent/child process relationships.5\. Distinguish suspicious behavior from confirmed malicious activity.6\. Document investigation findings and conclusions.\## Recommended SOC ResponseIn a production environment, repeated failed authentication followed by discovery commands would warrant additional investigation.Recommended investigative actions would include:\- Review surrounding authentication events.\- Determine whether authentication eventually succeeded.\- Identify the originating host and account.\- Review process ancestry and command-line activity.\- Check for privilege escalation.\- Review network connections associated with the account.\- Search for persistence mechanisms.\- Correlate endpoint activity with SIEM data.\- Escalate if evidence indicates unauthorized access or compromise.\## Tools Used\- Windows 11\- Windows Event Viewer\- Windows Security Event Log\- `auditpol`\- Command Prompt\- PowerShell\- Event IDs 4625 and 4688
